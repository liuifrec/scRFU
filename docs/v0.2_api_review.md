# scRFU 0.2 Public API Review

This review records the intended 0.2 compatibility boundary. The installed
version remains 0.1.0 until release metadata and version policy are confirmed.

## Stable public surface intended for 0.2

- `scrfu.adapters`: `AdapterResult`, `prepare_receptors`,
  `get_receptor_adapter`, `list_receptor_adapters`, `adapt_airr_dataframe`,
  `adapt_wells_tcr_ir`, and `adapt_cellranger_vdj`.
- `scrfu.pp`: `canonicalize_receptor_table`, `validate_receptor_table`,
  `receptor_schema`, and the documented normalization helpers/constants.
- `scrfu.io`: selective H5AD readers, generic receptor-cache read/write/
  validation/migration, ordinary H5AD read/write, hashing helpers, and
  `export_rfu_matrix`.
- `scrfu.tl`: `call_rfu`, `call_rfu_repo`, `call_rfu_table`,
  `validate_airr`, legacy summaries, `repertoire_metrics`, `rfu_metrics`,
  `rfu_pseudobulk`, `rfu_overlap`, `rfu_phenotype_coupling`, and
  `rfu_sequence_matrix`. Structured results are `RFUTableResult`,
  `RFUPseudobulkResult`, and `RFUOverlapResult`.
- `scrfu.pl`: the legacy RFU bar/heatmap/histogram and the generic metric,
  overlap, convergence, phenotype, and repertoire-comparison plots.
- `scrfu.wells`: Wells-only selective reader/cache compatibility utilities.

These are reachable through the documented `scrfu.adapters`, `scrfu.io`,
`scrfu.pp`, `scrfu.tl`, `scrfu.pl`, and `scrfu.wells` namespaces. Users do not
need to import `summary`, `repertoire`, `downstream`, `sequence`,
`tl_rfu_repo`, or backend implementation modules directly.

## Internal and unstable implementation

Underscore-prefixed helpers, everything in `scrfu.backends.rfu_chunks`, the
layout of chunk scratch directories beyond its documented validation contract,
and the implementation modules listed above are internal. Backend capability
classes are useful for integration but remain lower-level than `scrfu.tl`.

## Compatibility wrappers and ambiguous names

`call_rfu()` and `call_rfu_repo()` are AnnData compatibility APIs delegating to
the canonical table core. `aggregate_rfu()` and `rfu_heatmap()` are retained,
but they aggregate arbitrary AnnData groups and should not be described as
biological-sample pseudobulk. `rfu_summary()` is an assignment summary, not a
repertoire analysis.

In `rfu_metrics`, the historical columns `rfu_cell_count`,
`rfu_cell_abundance`, `sequence_convergence_ratio`, `multiplicity`,
`dominant_clonotype_fraction`, and `rfu_threshold_pass_rate` remain temporary
compatibility aliases. Their precise replacements are `cell_abundance` (a
count), `normalized_convergence`, `mean_sequence_multiplicity`,
`dominant_sequence_fraction`, and `threshold_pass_rate`. In particular,
historical `rfu_cell_abundance` is a within-group proportion, despite its
ambiguous name. A future major release may deprecate the aliases after a
warning cycle.

## AnnData contract

RFU calling reads `adata.obsm[airr_key]` (or the documented Wells TCR_IR
locations) and observation identifiers. Summaries and downstream functions
read explicitly named `adata.obs` columns. AnnData RFU wrappers write
`trb_cdr3aa`, `trbv`, `rfu_label`, and `rfu_score` to `adata.obs`, plus package
and RFU provenance below `adata.uns["scrfu"]`. Table APIs do not mutate input.

## Canonical receptor rows

Required fields are `input_row_id`, `cell_id`, `chain`, `cdr3aa`, `v_call`,
`productive`, `source_adapter`, and `source_row_id`. Optional fields include
counts, V(D)J calls, nucleotide junction, clonotype identity, source slot,
receptor type, and light-chain information. Adapter-specific trace fields such
as Cell Ranger `contig_id` may be retained in addition to this minimum.

## Canonical RFU results

Per-row results retain `input_row_id` and canonical receptor/source fields and
add `unique_sequence_id`, `eligibility_status`, `rfu_id`, `rfu_label`,
`rfu_score`, `pass_thr`, and `rfu_status`. `RFUTableResult` also exposes the
deduplicated per-sequence table, reconstruction mapping, and provenance.

## Release findings requiring confirmation

The distribution is named `scrfu`, requires Python >=3.10, uses MIT licensing,
and is currently version 0.1.0. The author email and all project URLs still
contain `REPLACE_ME`; no documentation URL is declared. These values must be
confirmed by the maintainer rather than guessed. The breadth of the adapter,
cache, execution, and downstream API changes justifies a 0.2.0 release once
metadata are fixed and release policy is confirmed.
